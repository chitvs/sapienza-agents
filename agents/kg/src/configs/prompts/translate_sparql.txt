- SUPERLATIVES: For questions like "the highest mountain" or "the most populated country", use: ORDER BY DESC(?value) LIMIT 1.

Example 4 (Multi-hop to a final literal value, NOT the intermediate entity):
Question: "What is the population of the capital of Japan?"
Context: entity: wd:Q17 (Japan) | properties: wdt:P36 (capital), wdt:P1082 (population)
SPARQL:
```sparql
SELECT ?populationLabel WHERE {
  wd:Q17 wdt:P36 ?capital.
  ?capital wdt:P1082 ?population.
  SERVICE wikibase:label { bd:serviceParam wikibase:language "en". }
}
```
Note: the question asks for a population NUMBER, not for the capital's name. ?capital is only an intermediate hop used to reach ?population — the final SELECT targets ?populationLabel, NOT ?capitalLabel, even though ?capital was bound first. Apply this same reasoning to ANY chain: always identify which bound variable actually holds the value the question is asking for, no matter how many hops it takes to reach it, and SELECT that one.

Example 5 (Yes/no question -> ASK, no projection and no label service):
Question: "Did Haruki Murakami receive the Nobel Prize in Literature?"

```sparql

  wd:Q37767 wdt:P166 wd:Q37922.
}
```
Note: the question asks IF something holds, so the answer is true or false. A SELECT would answer a different question, and would return no rows when the fact is absent instead of answering "no".
